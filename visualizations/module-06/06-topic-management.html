Topic 6

Topic management via Confluent CLI & Control Center

The CLI and the web UI change the same cluster. Every click in Control Center has a confluent kafka topic command behind it. Create, describe, update and delete topics with either one, and the page shows the matching steps in the other. Switch the target to see the differences: on Confluent Cloud you can't choose the replication factor, and on the shared Platform cluster RBAC only lets you work with l07.* topics.

Admin takeaway: use the UI to explore, and the CLI for anything you will repeat. A script of confluent kafka topic create … --if-not-exists commands can be reviewed in git, re-run safely, and replayed on a new environment. That is what capstone phase B5 asks for. A topic created by clicking leaves no record of its settings.
Admin gotcha: --force and a wrong context are a dangerous combination. On Apache Kafka, kafka-topics.sh --delete never asked you to confirm. The Confluent CLI does, unless you pass --force. Keep that prompt in interactive use, and in scripts check confluent context list before any delete.
