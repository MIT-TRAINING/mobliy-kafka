Confluent Control Center walkthrough

Control Center (C3) is the web UI of self-managed Confluent Platform. It runs on port 9021 and shows in a few clicks what took several kafka-*.sh commands in Module 2. This is a simplified model of it. Click the menu, topics and consumer groups to complete the four missions. Then stop broker-2 or slow down billing-svc, and find the problem from the UI.

Where to look in Control Center

QuestionControl CenterApache CLI equivalent (Module 2)
Is the cluster healthy?Cluster overview: brokers online, under-replicated and offline partitionskafka-topics.sh --describe --under-replicated-partitions
Which broker is slow or down?Brokers: status, throughput, partitions per brokerkafka-broker-api-versions.sh, kafka-metadata-quorum.sh, JMX
How is a topic configured?Topics → topic → Configurationkafka-configs.sh --describe --entity-type topics
What is in a topic?Topics → topic → Messages (browse by offset or time)kafka-console-consumer.sh --from-beginning
Is a consumer falling behind?Consumers → group: lag per partitionkafka-consumer-groups.sh --describe --group …
Are connectors and queries running?Connect and ksqlDB pagesConnect REST API on :8083, ksqlDB CLI

How Control Center gets its data

Management pages (topics, configs, consumer groups) call the cluster's admin APIs. Monitoring charts need metrics: the brokers report them to Control Center. In CP 8.x, Control Center stores metrics in Prometheus. Older 7.x versions stored them in internal _confluent-* topics. If the metrics configuration is missing, the management pages work but the charts stay empty.

Control Center vs Cloud Console

Confluent Cloud has no Control Center. Its web UI is the Cloud Console at confluent.cloud, with the same ideas (topics, messages, consumer lag, connectors) and the Metrics API for monitoring. Your lab uses both: the Cloud Console for env-l07, and Control Center for the shared CP cluster.

Admin takeaway: use Control Center to find a problem quickly, then confirm it on the command line before you change anything. For example, an under-replicated count in the overview should match kafka-topics.sh --describe --under-replicated-partitions. The CLI output can go into the incident ticket.
Admin gotcha: anyone who can open Control Center can do what their RBAC roles allow, and that includes Delete topic. On a shared cluster, give operations staff read-only roles (Module 7), and don't use a superuser account to log in to the UI.
