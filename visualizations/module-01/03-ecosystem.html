Topic 3

The Kafka ecosystem: producers, consumers, brokers, topics, partitions

Produce records with keys and watch the partitioner route them. Then scale the consumer group up and down to see how partitions are shared — and what happens when there are more consumers than partitions.

Producer

Client that writes records (key, value, headers, timestamp) to a topic. Chooses the partition from the key.

Topic & partition

A topic is a named stream split into partitions: ordered, append-only logs. Each record gets an increasing offset.

Broker

A Kafka server that stores partitions and serves reads/writes. Each partition has one leader broker at a time.

Consumer

Client that reads records by pulling from partitions, tracking its position with offsets.

Consumer group

Consumers sharing a group.id. Each partition is assigned to one member of the group.

Rebalance

When members join or leave, the group coordinator redistributes partitions across the remaining members.

Consumers in group order-processors: 2
The default partitioner computes murmur2(key) % numPartitions (this page uses a simpler hash for display). Same key → same partition → ordered processing per key. Records without a key are spread across partitions (the modern sticky partitioner fills a batch for one partition, then moves on).
Admin gotcha: you can increase a topic's partition count but never decrease it — and increasing it changes the key → partition mapping for new records, which can break per-key ordering. Try it with the slider: after changing partitions, cust-42 may land somewhere new.
