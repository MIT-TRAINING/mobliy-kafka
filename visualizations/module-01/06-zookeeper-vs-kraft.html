ZooKeeper vs. KRaft — where cluster metadata lives

Every cluster must track brokers, topics, partitions, leaders, ISRs and configs. Historically that metadata lived in an external ZooKeeper ensemble. KRaft (Kafka Raft) moves it into Kafka itself, as a replicated metadata log managed by a quorum of controllers. Kafka 4.0 runs in KRaft mode only.

Side by side

ZooKeeper modeKRaft mode
Metadata storeZnodes in a separate ZooKeeper ensemble__cluster_metadata log, replicated by Raft across controllers
Systems to operateTwo (Kafka + ZooKeeper), each with its own config, security, monitoringOne — Kafka only
ControllerOne broker, elected by racing for the ephemeral /controller znodeQuorum of controller nodes; one active leader elected via Raft
Controller failoverNew controller must re-read all metadata from ZooKeeper — slow with many partitionsStandby controllers already hold the log in memory — near-instant failover
Metadata propagationController pushes RPCs (UpdateMetadata, LeaderAndIsr) to every brokerBrokers pull (fetch) new records from the metadata log, like a consumer
ScalePractical limit ~200k partitions per clusterDesigned for millions of partitions
Key settingszookeeper.connect, broker.idprocess.roles, node.id, controller.quorum.bootstrap.servers (or .voters), controller.listener.names

Timeline

  • KIP-500Proposal (2019) to replace ZooKeeper with a self-managed metadata quorum.
  • 2.8KRaft early access.
  • 3.3KRaft marked production-ready for new clusters.
  • 3.5 – 3.9ZooKeeper mode deprecated; ZK → KRaft migration path. 3.9 is the last release that supports ZooKeeper.
  • 4.0ZooKeeper removed — KRaft only (2025). Confluent Platform 8.0 follows.

KRaft node roles (used in the hands-on lab)

Each node's process.roles decides what it does:

process.roles=broker            # data plane only
process.roles=controller        # metadata quorum only
process.roles=broker,controller # combined — dev/local only

A new KRaft node's storage must be formatted with a cluster ID before first start:

bin/kafka-storage.sh random-uuid
bin/kafka-storage.sh format -t <uuid> -c config/server.properties
