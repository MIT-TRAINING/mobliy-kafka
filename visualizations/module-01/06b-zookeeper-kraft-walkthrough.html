How a ZooKeeper cluster and a KRaft cluster actually work

Both kinds of cluster have to do the same four jobs: start up, create topics, notice a dead broker, and replace a dead controller. A ZooKeeper cluster stores its metadata in a separate system and the controller pushes changes to brokers. A KRaft cluster keeps metadata in its own replicated log, and brokers pull from it. Pick a scenario and step through it in one mode. Then switch modes and compare the steps, the messages, and the state on the right.

Where metadata livesZnodes in a ZooKeeper ensemble: a second distributed system with its own config, JVMs, security and monitoringThe __cluster_metadata log, replicated by Raft across the controller quorum

Is the broker alive?ZooKeeper session; it ends after zookeeper.session.timeout.ms (18 s) and the ephemeral znode is deletedBrokerHeartbeat; after broker.session.timeout.ms (9 s) without one, the broker is fenced
Choosing the controllerBrokers race to create the ephemeral /controller znode; /controller_epoch rejects stale controllersRaft vote among the controllers; the leader epoch rejects stale leaders
Telling brokers about changesThe controller pushes LeaderAndIsr and UpdateMetadata RPCsBrokers pull new records with Fetch, like a consumer of the metadata log
Controller failoverThe new controller reloads all metadata from ZooKeeper. This takes longer the more partitions you have.Standby controllers already have the log in memory. The new leader takes over in seconds.
Key settingszookeeper.connect, broker.idprocess.roles, node.id, controller.quorum.bootstrap.servers, controller.listener.names
Admin takeaway: run 3 controllers (survives 1 failure) or 5 (survives 2). Always use an odd number, because a quorum needs a strict majority. Check its health with kafka-metadata-quorum.sh --bootstrap-server $BS describe --status, which shows the leader, the epoch, the high watermark and how far each follower lags.
Upgrade gotcha: Kafka 4.x has no zookeeper.connect setting at all. If you inherit a ZooKeeper-based 3.x cluster, migrate it to KRaft on 3.9 (the last release with ZooKeeper support) before you upgrade to 4.x. Confluent Platform 8.x is KRaft-only for the same reason.
