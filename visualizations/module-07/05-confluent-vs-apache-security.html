Confluent vs Apache Kafka: ACLs, SASL & SSL

Apache Kafka builds security from separate parts: SSL listeners, SASL users and ACLs. Confluent adds identity sources (LDAP, service accounts), role bindings that bundle many ACLs into one role, and audit logs. Pick a real requirement and compare the three implementations. Watch how many statements each one needs, and move the team-size slider on requirement 3.

Migration tip: moving from Apache to Confluent doesn't require you to throw away ACLs. Confluent Server honours them next to RBAC. Translate the common patterns first: --consumer → two DeveloperRead bindings, --producer → DeveloperWrite, and prefixed All → ResourceOwner with --prefix. Then list what is left with kafka-acls.sh --list.
MQ admin gotcha: unlike MQ's setmqaut with a group, plain Apache Kafka ACLs cannot use your OS or LDAP groups. Each person needs their own ACLs, so 20 on-call engineers mean 20 sets. That growth, and forgotten ACLs after people leave, is the main reason teams adopt group-based RBAC.
