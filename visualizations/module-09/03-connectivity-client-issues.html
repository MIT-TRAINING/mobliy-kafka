Troubleshooting connectivity and client-side issues

"Can't connect to Kafka" is six different problems. A client has to resolve a name, open a TCP connection, complete TLS, log in with SASL, read metadata and then connect to every broker that metadata names. Build a client config for the Platform lab cluster, press Connect, and find the first step that fails. Each failure shows the error the client prints and the one command that tests that step on its own.

Press Connect.

5–6. Metadata, brokersThe same command: it lists every broker as advertisedConnection to node 1 (localhost/127.0.0.1:9092) could not be establishedFix advertised.listeners on the brokers (admin side)
Admin gotcha: bootstrap succeeding proves only that one broker answered. The client then connects to the hosts in the metadata, which come from each broker's advertised.listeners. If a broker advertises a name the client can't reach, the client hangs after a successful bootstrap. Check with kafka-broker-api-versions.sh, which prints every advertised broker address.
Production trap: a client with the wrong security.protocol often logs no exception at all, only Bootstrap broker … disconnected over and over until a timeout. When you see that line, check the protocol and SASL settings before you blame the network.
