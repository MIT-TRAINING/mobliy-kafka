Best-practice checklist for preventing message loss

No single setting prevents message loss. The producer, the topic, the brokers' placement, the consumer and your alerting each close a different gap. Start from a preset or tick items yourself, then press Run chaos drills. Nine failures hit the CDR pipeline, and each drill shows which unticked item let CDRs be lost or billed twice. Admin takeaway: the full checklist turns loss into visible failure. When two brokers die, writes are refused rather than half-stored, and when a batch expires the app is told. Being unavailable for a while is something you can recover from. Billing records that are silently missing are not.
Production trap: settings drift. Check them on a schedule instead of trusting the deploy: kafka-configs.sh --bootstrap-server $CP --command-config $CFG --describe --entity-type topics --entity-name l09.cdr.voice --all for each critical topic, and the effective producer config that every client logs at startup (ProducerConfig values:).
