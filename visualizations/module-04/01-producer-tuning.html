Producer configuration tuning

send() doesn't put a record on the wire. It drops it into a per-partition batch that ships when the batch is full (batch.size) or has waited long enough (linger.ms). Change the load and the knobs below, watch requests per second and latency move, then drop an ACK to see what idempotence is for.

ConfigException at startup: Must set acks to all in order to use the idempotent producer. Otherwise we cannot guarantee idempotence. — you set enable.idempotence=true explicitly with acks=1, so new KafkaProducer(props) throws. Set acks=all or turn idempotence off.

How idempotence works: the broker gives each producer a producer ID, and the producer numbers every batch per partition. If a retried batch arrives with a sequence number the leader already appended, the broker acknowledges it without writing it again. Try "Lose the next ACK" with idempotence on and off.
Admin gotcha: retries is not the real limit. The producer keeps retrying until delivery.timeout.ms (2 minutes by default) runs out, then fails the send() callback with a TimeoutException. If an app says records "expired after 120000 ms", look at broker health and NOT_ENOUGH_REPLICAS errors, not at the retry count.
