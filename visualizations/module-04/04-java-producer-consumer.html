The silent one: a brand-new group with auto.offset.reset=latest (the default) starts at the end of the log, so it reads nothing that was already there. Developers report "the consumer is broken". Before you touch anything, check with kafka-consumer-groups.sh --describe --group billing-svc.
Lifecycle rules worth enforcing in code review: create one KafkaProducer per app and share it (it's thread-safe); keep a KafkaConsumer on a single thread (it isn't); always close() in finally so the producer flushes and the consumer leaves the group cleanly. Spring Boot's KafkaTemplate and @KafkaListener, used in the lab projects, wrap exactly these classes.
