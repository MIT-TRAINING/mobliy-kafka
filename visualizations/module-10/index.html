Ecosystem, Migration, Backup/DR & Capstone

Interactive visualizations for each Module 10 topic. Each page has a hands-on simulation you can play with, followed by a 5-question self-quiz with explanations.

Objective: Administer the Confluent Kafka ecosystem and evaluate migration considerations from Apache Kafka to Confluent Kafka.

Confluent managed connectors (source/sink)

Run a CDR pipeline with a source and a sink connector, fully managed on Cloud or self-managed on Platform. Create, pause, break and fix them, and watch the task-hour bill.

Schema Registry: evolution & compatibility

Evolve the CdrVoice schema field by field under BACKWARD, FORWARD, FULL or NONE. See which changes the registry refuses and which consumers would break.

ksqlDB on Confluent

Feed calls into a stream and run push, pull and persistent queries on them. See which queries keep running on the server, the topics they create, and what you have to clean up.

Backup & DR: Replicator & multi-datacenter

Replicate cdr.voice to a second site with Replicator, MirrorMaker 2 or Cluster Linking. Fail the primary site, then measure what was lost (RPO), how long recovery took (RTO) and how many CDRs were billed twice.

Migration: Apache Kafka → Confluent

Move the billing pipeline from the Apache cluster to Confluent Platform: cut over consumers first, dual write, or big bang. Choose where the new consumer group starts, then count the pause, the CDRs lost and the CDRs billed twice.
