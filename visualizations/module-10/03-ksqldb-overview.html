ksqlDB on Confluent: streams, tables and the queries that never stop

ksqlDB runs SQL over Kafka topics. A push query streams rows to your terminal until you stop it. A pull query asks a table once, like a database. A persistent query keeps running on the server after you leave, writes to new topics, and is what an admin has to track and clean up. The stream lNN_calls already holds the lab's six calls. Run each query, insert more calls, then switch auto.offset.reset to latest, start over, and see what the new queries miss.

Admin gotcha: auto.offset.reset defaults to latest. A persistent query created without earliest ignores every record already on the topic, so the totals look wrong and nothing reports an error. The lab's ksql.sh sends earliest; the web editors need it set by hand.
Production trap: closing your terminal doesn't stop a persistent query. List them with SHOW QUERIES;. Dropping the stream or table created with AS SELECT also stops its query, and DELETE TOPIC removes its topic. Drop derived objects before the stream they read from.
