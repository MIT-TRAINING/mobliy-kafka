Comparing Confluent monitoring with Apache Kafka JMX and Prometheus

Apache Kafka publishes hundreds of JMX MBeans and leaves the rest to you. The course's Apache cluster runs a JMX exporter on every broker (:7071), Prometheus scrapes it, and Grafana draws it. Control Center bundles that pipeline, and on Confluent Cloud there is no broker to scrape at all. Pick a question an on-call engineer asks, and follow it through all three stacks. Then break the scrape and see what Prometheus tells you.

Admin takeaway: the Prometheus names come from the exporter's rules, not from Kafka. In the lab, kafka.server:type=ReplicaManager,name=UnderReplicatedPartitions becomes kafka_server_replicamanager_underreplicatedpartitions_value. Change the rules and every dashboard and alert that uses the old names breaks without an error. Keep kafka.yml under version control with your dashboards.
Monitoring gotcha: a missing series is not the same as a zero. If broker 12's scrape fails, its URP series disappears and sum(…) > 0 stays quiet. Always add up == 0 (or absent(…)) alerts, so a broken monitoring path pages you too.
