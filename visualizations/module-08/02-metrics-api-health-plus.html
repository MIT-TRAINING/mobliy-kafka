Confluent Metrics API and Health+

On Confluent Cloud you can't scrape a broker. Confluent publishes your cluster's metrics through the Metrics API, and you query them with a Cloud API key. On self-managed Confluent Platform, it works the other way round: the brokers send telemetry out to Health+, which watches the cluster for you. Health+ is now being retired (see below), but its successor works the same way. Build a query for your Basic cluster lkc-4n8vq and read the answer, then switch to Health+ and find the three ways its alerts can fail to reach you.

Admin gotcha: received_bytes and sent_bytes are delta counts: each point is the bytes
    in that time bucket. With PT1M, 360 000 000 means 360 MB in that minute, or 6 MB/s. Change the granularity to
    PT5M and the same traffic shows five times larger values. Divide by the bucket length before you compare.

  
Plan for the sunset: the course's Platform cluster runs 8.3, a new deployment in Health+ terms, so
    Health+ is shown here as an overview only. The replacement, Unified Stream Manager, runs an agent in your network that streams
    operational data to Confluent Cloud, so Platform and Cloud clusters appear in one Cloud UI. It needs Confluent Platform 7.9.6+ or 8.1+ and private
    networking to Confluent Cloud. The egress problem below applies to it as well.

  
Production trap: the lab's Platform cluster sits in private subnets. Health+ only works if the brokers
    can reach Confluent Cloud on 443 through the NAT gateway (infra/confluent/README.md opens that egress for Module 8).
    If a firewall change later closes it, the cluster keeps running and alerts just stop arriving. Add a check that the
    cluster still appears as reporting in Health+, so a silent channel is noticed.
